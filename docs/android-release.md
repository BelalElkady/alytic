# Android: build, sign and publish

Project: `frontend/android` (generated by Capacitor 8). Application id `com.egxpert.app`,
`minSdk 24`, **`compileSdk` / `targetSdk` 36**.

> **Target API check (2026-09-30).** Google Play: from **31 Aug 2026** new apps and updates
> must target **Android 16 / API 36** or higher (extension request possible to 1 Nov 2026) —
> <https://developer.android.com/google/play/requirements/target-sdk>. Capacitor 8.5 generates
> `targetSdkVersion = 36` (`android/variables.gradle`). Re-check that page before each release.

> **Not verified in the authoring environment.** It had no Android SDK / device, so the
> Gradle build, R8 shrinking, App Links and push were **configured but never run**. The
> `Mobile — Android` workflow and a physical-device test are the first real checks. Expect
> to fix small things on the first build.

## Prerequisites
Node 22, bun, **JDK 21**, Android Studio (Ladybug+ / current stable) or the command-line SDK
with platform 36 + build-tools, a physical device for push.

## Everyday development
```bash
cd frontend && bun install
bun run cap:android          # builds the web bundle, syncs, opens Android Studio
# or, with a device/emulator attached:
bun run cap:run:android
```
Debug builds may talk to a local backend: `MOBILE_ENV=development bun run cap:sync`
(uses `http://10.0.2.2:8080/api/public`; cleartext is allowed **only** by
`android/app/src/debug/res/xml/network_security_config.xml`, which is not in release builds).
Inspect the WebView at `chrome://inspect` (enabled for non-production builds only).

After changing anything under `src/`, re-run `bun run cap:sync` (it rebuilds the bundle).

## Firebase (push)
Add `google-services.json` for package `com.egxpert.app` to `frontend/android/app/`
(git-ignored). The google-services Gradle plugin is applied automatically when the file
exists. See `docs/push-notifications.md`.

## Signing
Google Play App Signing is used: you sign uploads with an **upload key**, Google re-signs
with the app signing key.

```bash
keytool -genkeypair -v -keystore ~/egxpert-upload.jks -alias egxpert-upload \
        -keyalg RSA -keysize 4096 -validity 10000
```
Store the `.jks` and its passwords in a password manager — **losing the upload key is
recoverable (Play support), leaking it is not safe**. Never commit it.

Local release builds read `frontend/android/keystore.properties` (git-ignored):
```properties
storeFile=/home/you/egxpert-upload.jks
storePassword=…
keyAlias=egxpert-upload
keyPassword=…
```
CI reads the same values from environment variables / secrets (below). With no keystore
configured the release build is **unsigned** — it never silently falls back to the debug key.

## Build the signed release bundle
```bash
cd frontend
MOBILE_ENV=production bun run cap:sync          # production web bundle + secret scan + sync
cd android
./gradlew bundleRelease \
  -PversionCode=12 -PversionName=1.0.3          # versionCode must increase on every upload
# → app/build/outputs/bundle/release/app-release.aab
# → app/build/outputs/mapping/release/mapping.txt   (upload to Play Console → deobfuscation file)
./gradlew assembleRelease                        # optional signed APK for sideload testing
```
R8 (`minifyEnabled`, `shrinkResources`) is on for release; rules in `app/proguard-rules.pro`
keep Capacitor plugins. **Test the release build on a device** — obfuscation bugs only show
there. Verify the certificate: `apksigner verify --print-certs app-release.apk`.

## CI (`.github/workflows/mobile-android.yml`)
Every push/PR: frontend tests → web build → mobile build + bundle secret scan → `cap sync` →
Gradle `lintDebug testDebugUnitTest assembleDebug` → uploads the debug APK. A manual run
with *release = true* also builds the signed `.aab`. Secrets (Settings → Secrets → Actions):

| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 egxpert-upload.jks` |
| `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` | from the keystore |
| `GOOGLE_SERVICES_JSON_BASE64` | `base64 -w0 google-services.json` (optional; push needs it) |

## App Links
The manifest declares verified links for `egxpert.com` / `www.egxpert.com` and the
`egxpert://` scheme. Host `assetlinks.json` with the **Play app signing** SHA-256 (and the
upload key's for internal testing) — `docs/deep-links.md`.

## Google Play checklist
- [ ] Play Console developer account (identity verification; new personal accounts must run a closed test — check current requirement)
- [ ] Create app; **Play App Signing** enabled; upload `.aab`
- [ ] `targetSdk` 36 ✔ (re-verify date requirements)
- [ ] **Data safety** form — from `docs/mobile-privacy.md`
- [ ] **Privacy policy URL** updated (push tokens, FCM, deletion, AI provider)
- [ ] **Account deletion**: in-app ✔ + a public web URL for deletion requests
- [ ] **App access**: give reviewers a demo account (email-verified, active trial)
- [ ] **Payments policy decision** — `docs/mobile-store-compliance.md` §1 (manual InstaPay vs Play Billing)
- [ ] Financial-features declaration, content rating, target audience, ads = none
- [ ] Store listing: Arabic + English text, 512 px icon, feature graphic, phone screenshots
- [ ] Notification permission (Android 13+) behaves: not asked at launch ✔
- [ ] `assetlinks.json` live and verified (`adb shell pm get-app-links com.egxpert.app`)
- [ ] Upload `mapping.txt`; start with **Internal testing** → Closed → Production
- [ ] Pre-launch report clean (crashes, accessibility)
