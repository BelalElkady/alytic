# Alytic

Arabic-first EGX investing desk, sold as EGXpert and as white-label sites. Use the terms in `CONTEXT.md` in code, copy and issues; user-facing text is Egyptian Arabic.

## Stack and folders

- `backend/`: Node 20+, Express 5, ESM JavaScript, npm. Nearly every route is in `src/api/server.js`; database calls live in `src/db.js` and go through the tenant-aware client in `src/supabaseClient.js`.
- `backend/src/agent/`: the AI analyst layer (OpenRouter); model output is checked against the zod schemas in `schemas.js`.
- `backend/src/tenancy/`: each white-label tenant has its own Supabase project, picked per request (`WHITE-LABEL.md`). Market data lives only in the platform database.
- `backend/supabase/`: `schema.sql` (every tenant), `platform.sql` (platform database only), one-off `patch-*.sql`, and the `evaluate-recommendations` Edge Function.
- `frontend/`: TanStack Start + Vite + React, TypeScript, bun. Synced with Lovable: read `frontend/AGENTS.md` before touching it.
- `tests/e2e/`: Playwright, run from the repo root.

## Commands

- Self-check with `node --check <file>`. Run test suites, builds and lint only when the user asks; they spend the user's CI and test-project budget.
- Tests: `npm test` (all three layers), `npm --prefix backend test`, `bun run --cwd frontend test`, `npm run test:e2e`. Isolation and fixtures: `TESTING.md`.
- Frontend: `bun run --cwd frontend lint`, `bun run --cwd frontend build`.
- Security: `npm --prefix backend run security:check`.
- Tests and security checks run on pull requests only; a push to `main` deploys to production without running them again (`.github/workflows/deploy.yml`). Work on a branch and open a PR, and merge only once its checks pass.

## Security rules

- Scope every read and write of user data by `req.user.id` from the session, and check any portfolio or record id from the request against that user.
- `/api` requires login except for the explicit allowlist in `server.js`. Adding a path there makes it public; call it out in the PR.
- `/api/admin` is for Admins with a verified email. Marketers reach only what `MARKETER_READS` lists, so a new admin route stays closed to them until it is added there on purpose.
- An endpoint that carries the product's value or spends money per call goes in `PAID_PATHS`. Portfolio reads and exports stay open to lapsed accounts.
- Shared market data (`/api/admin/indices`, `/api/admin/announcements`, `/api/platform`) is edited from the main site only (`canEditIndices`, `isPlatformAdmin`).
- Validate every request field in the handler before using it (type, length, range, format) and answer 400 with an Arabic message. A new route with a multi-field body validates it with a zod schema (`safeParse`); existing hand-written checks stay as they are.
- Wrap handlers in `wrap()`: it sets the tenant context and turns unexpected errors into the generic message.
- Keep `case sensitive routing` on; every gate compares `req.path` case-sensitively.
- Secrets come from the environment only (`backend/.env`, GitHub secrets). Only `VITE_*` values reach the browser, so a secret never gets that prefix; the service-role key stays in `backend/`.

## Database

- SQL that already ran in production stays as written. Change the schema with new idempotent statements (`if not exists`) appended to `schema.sql`, or a new `patch-*.sql` whose header says where, when and in what order to run it.
- Production is `xssjwnevhbpcdmtbatiy`; tests use `qfxuejkbnrdszycqxvdx`. Agents read production only; schema changes and data fixes there go through the user.
- Recommendations are append-only: logged once, never edited.

## No-touch areas

- `frontend/src/routeTree.gen.ts` (generated by the router plugin).
- `backend/src/config/universe.generated.json` (rebuilt by `npm --prefix backend run build:universe`).
- Published git history: Lovable syncs pushed commits, so add new commits rather than rewriting pushed ones.
- Billing is manual InstaPay plus Admin Activation by decision; keep payment flows on that path.
- `.env` files and anything under `backend/data/` the app writes at runtime.
